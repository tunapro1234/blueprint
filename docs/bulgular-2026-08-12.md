## 4. K2 — Görev-kapsamlı oturumlar (Tuna'nın tasarımı; ilk tercih)

Tuna'nın tarifi: alan ajanı (fon) uzun ömürlü kalır ama **iş başına özel görev oturumu**
açılır, görev kendi içinde kalır, bitince md'ye kaydedilip kapanır; dosya sistemi ortak
hafızadır.

**Sektör karşılığı birebir var.** Anthropic'in kendi reçetesi: *"artifact systems where
specialized agents create outputs that persist independently... pass lightweight references
back to the coordinator"* (gerekçe: "game of telephone"). spec-kit #3507 aynı tasarımı
kelime kelime talep ediyor. Manus: "filesystem as the ultimate context". Kiro/Backlog.md/CAO
ürünleşmiş halleri.

**Eksik olan desen değil, muhasebe — üç parça:**
1. **Makine-okunur durum:** her görev klasörüne `status.json` (Kiro `spec.json` kalıbı:
   faz+onaylar+artefakt yolları) + alanın tek `INDEX.md`'si. Kural (memsearch'ten):
   **"Markdown is the source of truth, index is derived and rebuildable"** — CAO #444'te
   index kaybı hafıza kaybına dönüştü, o hata sınıfına girilmeyecek.
2. **Kapanış kanıtla ve bloklanarak doğrulanır:** `Stop`/`SubagentStop` hook'u exit 2 /
   `{"decision":"block"}` ile ajanı durdurmuyor — beklenen SONUC.md yoksa kapanamaz.
   (`SessionEnd` bloklayamaz, ona güvenme.) İçerik şablonu Backlog.md'den: AC'ler kanıtsız
   işaretlenmez; `NOTLAR.md` (süreç) ile `SONUC.md` (PR-tarzı kapanış) ayrı.
3. **Değişmez kısıtlar ayrı dosyada, zorunlu okunur.** Cognition itirazının (izole görevler
   çatışan karar alır) tek panzehiri. Ölçüm: kısıt özete taşındıysa ihlal %0, atlandıysa %38.

**Önerilen şema (fon örneği):**
```
/srv/probot/fon/
  KISITLAR.md      # değişmez kısıtlar; kısa; her görev oturumu ZORUNLU okur
  INDEX.md         # tek satır/görev: slug · tarih · durum · yol
  BILGI/           # alan bilgisi (BASVURABILIR, UNIVERSITELER, BIGG...)
  basvurular/itu-cekirdek/
    GOREV.md       # brief: hedef, teslim tanımı, okunacak 3-5 dosya, kısıt kopyası
    status.json    # faz+onay+artefakt yolları (md'den türetilebilir)
    NOTLAR.md      # süreç: kararlar+gerekçe, blokerler
    SONUC.md       # kapanış: ne yapıldı, doğrulama kanıtı, açık sorular
    arastirma/     # ham notlar (zaten var)
```
Bu, HANDOFF-N zincirini de emekli eder: kısıtlar KISITLAR.md'de (tek yer), durum INDEX'te,
sonuç görev klasöründe. Artımlı devir notu ihtiyacı kalkar.

**bp yüzeyi (ince katman):** `bp task start <alan> <slug>` (klasör+GOREV.md+oturum aç,
agentbook'a alt kayıt) ve `bp task close <ad>` (kapanış ritüeli gönder → SONUC.md'nin
yazıldığını DOĞRULA → yazılmadıysa reddet → INDEX'e satır ekle → oturumu kapat).

**Alternatifler (bakıldı, gerekçeyle ikincil):**
- *Mevcut hâl + daha iyi compaction:* ölçülmüş en kötüsü — kısıt kaybı %0→%30, kazanç
  tarafı için hiç benchmark yok, paylaşımı çözmüyor.
- *Görev başına subagent:* bağlamı izole eder ama **attach edilemez** (Tuna'nın ana şartı),
  ana oturum yine büyür, ~15× token.
- *Görev başına worktree/container:* çakışmıyor, üstüne biner; aynı repoya eşzamanlı
  dokunuşta gerekir (container-use).
- *Durumsuz görev kuyruğu:* bağlam problemi yapısal olarak kalkar ama alan uzmanı kaybolur,
  her brief'i Tuna yazmak zorunda. Mekanik iş için doğru (codex'in yeri), fon için değil.
- *Codex `/agent` alt-thread'leri / Anthropic agent teams:* yerli ama hub-spoke / deneysel /
  oturum-kapsamlı / önerilen boyut 3-5.

**A/B ölçümü yok** (açıkça: bulunamadı). Dolaylı destek: Anthropic context-management
%39 iyileşme + %84 token azalması; Chroma LongMemEval ~300 küratörlü token ~113k tam

## 5. K4 — Model ekonomisi ve Codex'e geçiş

**"Param bitiyor" teşhisi:** maliyet üretimden değil, bağlamın her turda yeniden

tasarruf mekanizması.** Gerçek iki problem: (a) 255k/istek **kalite** bölgesinin dışında

vs read 0,1×) ve 22 soğuk ajan her uyanışta bunu ödüyor.

**Bağlamı yarıya indirmek = faturayı yarıya indirmek + kaliteyi artırmak.** Hiçbir model
arbitrajı bu ikiliyi vermiyor.

**Codex'e geçiş:** hukuken temiz (`codex login` resmi), bp'de `--codex` hazır, agentbook'ta

## 6. K5/K6 — Bağlam yönetimi: mekanik gerçekler ve hamleler

Kaynak: code.claude.com/docs (prompt-caching, memory, sub-agents) — kendim doğruladım.

**Mekanik gerçekler:**
- Cache prefix-eşleşmeli; katman sırası **tools → system → messages**, üsttekinin değişimi
  altını komple geçersiz kılar. Oturum ortasında MCP eklemek/çıkarmak en pahalı hata.
  `defer_loading` prefix'e dokunmaz (bizde etkin görünüyor; filoda ajan ajan doğrulanmalı).
- **`/compact` en pahalı anını soğuk oturumda yaşar** (özet isteği tüm geçmişi cache'siz
  yeniden işler). `bp compact` politikası şu an tam bu anı hedefliyor → **düzeltilmeli**:
  geçmiş gerekmiyorsa `/clear` bedava; gerekliyse ve ajan tekrar kullanılacaksa compact.
  Eksik boyut "dolu mu" değil "geçmiş gerekli mi".
- **Her CLI yükseltmesi filo çapında cache yıkımı** (system prompt değişir; 29 oturum ×
  7,3M token cache'siz yeniden okunur). 2.1.228 dün gece kuruldu → bugünkü ilk turlar bunu
  ödedi. `DISABLE_AUTOUPDATER=1` ile yükseltme kontrollü ana alınmalı. Aynı sınıf: effort
  değişimi de cache anahtarı (26 Tem toplu normalizasyonu tüm filo cache'ini yıktı).
- Aynı dizindeki paralel oturumlar **birbirinin cache'ini okur** (cwd paylaşan gruplar
  kazara kazanıyor; worktree = ayrı cache).
- `/rewind` ve `/recap` cache-güvenli; kısıtlar oturum ortasında `messages`'a
  `{"role":"system"}` eklenerek cache bozulmadan yeniden pinlenebilir.
- Auto-compact eşiği `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` ile kaydırılabilir; `PreCompact`/
  `PostCompact` hook'ları var (compact öncesi transcript arşivi bp'ye uygun iş).
- Filoda "autocompact thrashing" yaşayan tek oturum **blueprint'in kendisi** (3 kez; bu
  araştırmada büyük HTML/çıktıları bağlama sokmamın bedeli — büyük çıktı dosyaya gidip
  dilimle okunmalı; kural: tool çıktısı eşiği aşarsa bağlama girmez).

**Öncelik sıralı hamleler (ölçüm dayanaklı):**
1. **22 soğuk ajanı devirle parkla** (compact ile DEĞİL): soğumadan ÖNCE devir artefaktı +
   oturum kapat; uyanma = taze oturum + artefakt. Dayanak: Chroma LongMemEval (~300 küratörlü

5. **Cache hijyeni:** volatil şey prefix'e girmez; oturum ortası tool seti/effort değişmez;

**Yapılmayacaklar:** auto-compaction'ı birincil mekanizma yapmak · transcript üzerine RAG
